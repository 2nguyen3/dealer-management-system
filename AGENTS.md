# Agentra project instructions

## Context

Agentra is a Dealer Management System (DMS), an Introduction to Software Engineering
course project (UIT, VNU-HCM). Team and course details are in the root `README.md`.

Current application (after the 14/11/2026 simplification, owning plan
`openwiki/backend-design/plan/simplification/`):

- Three document kinds: stock receipt (PN), stock issue (PX), payment receipt (PT),
  lifecycle DRAFT → POSTED → CANCELLED; cancel/correct only in the current month and
  with a reason. Balances live in `agency.debt`, `product.stock`, `lastPurchasePrice`.
  Business rules QĐ1–QĐ8 plus AGENCY_HAS_DEBT.
- Authentication/administration, master data (agency types, units, products, agencies,
  wards, business rules), VNPAY sandbox online payments (QR + payment request PDF),
  document history, five reports and a dashboard: 91 API operations
  (`openwiki/backend-design/API/openapi.json`, generated by `backend/scripts/gen_openapi.py`).
- React UI covers all of them in 24 languages, with a GUIDE per page and a Portal.
- The chatbot (M32, MCP + OpenRouter direction) is not built.
- Removed on request 14/11/2026: upfront payments, refunds, credit, receivables/FIFO,
  stock counts, returns, adjustments, revisions, idempotency commands. Older
  M-numbered plans and checkpoints under `openwiki/` are history, not current behavior.

## Working conventions

- Inspect existing patterns and user changes before editing; keep changes focused.
- Backend features live in `backend/app/modules/<feature>/` (router, schemas, models,
  service, repository, dependencies). Routes delegate to services; request-scoped
  synchronous sessions with explicit commits; repositories never commit or roll back.
  `app/api/router.py` aggregates routers; shared helpers in `app/common/`,
  infrastructure in `app/core/` and `app/db/`.
- UI features live in `ui/src/features/<feature>/`; shared code in `src/lib/`,
  composition in `src/app/`. Every new `t()`/`msg()` string needs all 23 locale files.
- New endpoints: regenerate the contract and update operation counts in docs/tests.
- Update documentation when changing settings, commands, endpoints or structure.
- Backend uses `uv.lock`, frontend `package-lock.json`; keep locked installs and update
  the lockfile with dependency changes.

## Security

- Never commit `.env` files or credentials; `DB_PASSWORD` stays blank in templates.
- Do not print resolved Compose configuration or env values containing secrets.
- The passwords in `openwiki/cred/account/account.md` are synthetic application
  accounts (also in `backend/app/db/seed_data.py`), not database or provider credentials.
- Keep provider credentials and personal model choices in user-level tool settings.
- Commit and push only when requested; use conventional messages; never force-push or
  rewrite history without an explicit request.

## Verification

Run checks from the owning directory; the command list is in
`.agents/workflows/verify.md`. Report the commands actually run, their results and
anything left unverified.

## Database

- Schema authority: immutable reviewed DDL in `backend/alembic/sql/`. Head `0011`
  (`0011_simplified_schema.sql`) drops and rebuilds schema `dms` (16 tables, 22 function
  codes, `dms.clock`/`dms.app_now()`, balance guard triggers); it cannot be downgraded.
  Add new revisions for schema changes; never edit deployed SQL snapshots.
  `alembic check` must stay clean.
- From `backend/`: `uv sync --frozen`, `uv run alembic upgrade head`,
  `uv run python -m app.db.seed`, `uv run python -m app.db.verify --seeded --regression`
  (83 regression checks in a separate schema, rolled back).
- Seed v2 replays history from 01/06/2026 to the day before seeding through
  `DocumentService`; it refuses a non-head or partially populated schema, and a rerun
  only verifies. It never disables triggers or writes balances directly, and texts must
  stay realistic (`verify --seeded` scans for placeholder words).
- Seeding over the network to Neon takes ~70 min; production was seeded locally on
  PG18 and restored onto Neon with `pg_restore` in one transaction.

## Runtime and deployment

- Production database: Neon PostgreSQL 18, Singapore (pooled host). The backend reads
  `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SSLMODE` from
  `backend/.env` (raw password, not URL-encoded). Local Docker uses the same production
  database, so do not create test business data through it.
- Docker: `docker compose build`, then `docker compose up -d --force-recreate --wait`.
  UI on http://localhost:8080, API on localhost:8000, docs at `/api/docs`. Migrations
  run explicitly, never on API startup. See `.agents/workflows/docker.md`.
- Vercel: project `agentra-dms`, alias https://agentra-dms.vercel.app, functions pinned
  to `sin1`. Deploy with `npx --yes vercel@65.12.1 deploy --prod` from the repo root;
  upload env with `backend/deploy_vercel_env.py`.
